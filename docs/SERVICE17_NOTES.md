# Roster, Active Service Calls and Shared Popup Motion

26 October 2026, Asia/Singapore. Owner-requested public preview refinement. Supersedes service-call contact gating, full roster greyscale, profile-photo desaturation, asymmetric sheet animation and lock reveal timing in earlier notes.

- Availability remains independent of Staff arrival. During noon–18:00 the public roster evaluates the upcoming evening shift, rather than failing every person against the previous shift's finished time window. Current operational assignments, leave and package locks still apply. Arrival neither grants availability nor changes those records.
- Unavailable roster photos retain 50% saturation. Main photos inside public Staff profiles retain full colour, including unavailable Staff. Staff Roster remains read-only.
- Customer Call for Service appears only for their own Manager-started, active booking at a known table/room in the selected venue. A reservation alone or shift-arrival check-in is insufficient. The preview's existing Manager Start Service is the proxy for arrival/escort to the place; no separate customer-arrival workflow was invented.
- Staff can request service for an active table/room only with their own started, unended, uncancelled assignment session. Initial, added and replacement sessions qualify; merely scheduled, unrelated, ended or unassigned Staff do not. The fixed Staff preview identity remains Maya.
- Mirror/Waiter selection opens a confirmation popup before creating any Manager Actions item. Multiple eligible bookings have an explicit Booking ID / place selector. Confirmation rechecks role, venue, booking, live assignment and place. A location change invalidates the draft. No WeChat gate applies to these in-app requests; all other established WeChat booking/contact/removal guards remain.
- Requests retain Booking ID, table/room at request time, venue, actual customer, requester role/name/ID, type and time. Customer and Staff share duplicate prevention per booking/place/type. Managers see the routing location in both row and details, with selected-venue visibility and acknowledgement checks. Acknowledgement produces the existing Customer notice and, for Staff-originated calls, a Staff notice. All delivery is page-local simulation, not real push/Telegram delivery.
- `popup-motion.js` applies one shared two-second upward entrance to all current and future `[role="dialog"]`, `dialog` and `.app-popup` surfaces. Exit plays the identical frames/easing in reverse. Same-dialog content repaint does not replay entrance. Nested dialogs are tracked; cameras/timers stop immediately on close, while an inert, inaccessible visual clone finishes the exit. Exit clones cannot accept input and are removed on completion, timeout or lock entry. Early closure reverses from current progress. Reduced-motion preference removes animation. New popup code must use these standard semantic selectors.
- The opening/closing rule covers reservation dismissal, Back/Escape/backdrop, normal modal close and nested room images. Old sheet dismissal timers are removed so they cannot add a second exit or delay an action.
- Lock segment reveal durations and delays are halved: clock .325s/.025s, avatar/welcome .325s/.375s, task tiles .325s/.725s, Unlock .3s/1.05s. Existing splash and final lock geometry remain.
