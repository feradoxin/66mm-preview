# Payroll workspace and shared UI — Iteration 19

26 October 2026, Asia/Singapore. Owner-requested public preview work, developed in bounded checkpoints. Supersedes older placeholder Boss Payroll and pending-only Customer lock summaries.

Boss Payroll keeps Finalize → Tally → Paid Out in one workspace. More Payroll Tools opens Outstanding, Manager Funds, Revisions & Recovery, Reports and History. Period selection is shared; Finalize selects primary venue; Tally/Paid Out consolidate eligible Staff across venues. Sources must be completed/reconciled, including relevant cross-venue sources; another venue's whole payroll need not close. Finalization seals the venue's selected period. Period boundaries are first day 18:00 to next first day 18:00 MYT; Manager correction cutoff is following day-10 00:00 or earlier Boss finalization.

Tally is once per finalized entitlement and uses current Outstanding. Zero remainder says Settled by Tally and cannot produce a zero Paid Out. Positive full payouts require per-person confirmation. Boss direct recording does not debit Manager custody. Delegated preparation holds the named Manager's available company funds; Manager Manage → Entrusted Funds reports full external payment, definite nonpayment or uncertainty. Boss confirms reported full payments. Unknown/partial evidence retains reconciliation holds; paid/not-paid/keep-held decisions require evidence. Batch success remains when another item fails; retry links include only failed entries.

Outstanding adjustments require a Staff-visible description, current posting timestamp, optional reference date, internal reason and review. Manager fund advances/unused returns are Boss-reviewed and cannot consume held funds. Reviews bind current role, Manager identity and financial snapshot; duplicate IDs and stale or unknown commands refuse. Boss self-approval records a local mandatory-oversight entry, never a claim of an actual sent message.

Revisions preserve snapshots and prior payment/Tally facts. Positive changes produce difference-only supplements in the original period. Definitely unpaid reductions restore excess effective Tally explicitly. Paid reductions create separate recovery cases with reasoned repayment/write-off; no automatic Outstanding or future-wage debit. Uncertain payments and mixed linked supplement cases require reconciliation instead of a guessed rewrite. Unattempted prepared intent release is retained in review history.

Reports select concluded period, Staff/company scope, available individual version or latest, PDF/XLSX and one of four languages. These are request previews ONLY: no file generation, Telegram delivery or download link. All new Payroll balances are fictional page-memory fixtures, separate from older Staff Finance samples. Reload resets records. No bank transfer, durable journal, production authorization, payroll integration, real notification or server security is implemented.

Shared UI: popup close glyph X with localized accessible name; 95vw width, maximum 80dvh and internal overflow scroll; existing 200ms opening/125ms closing and footer-aware toast clearance retained. Unavailable roster photos have saturation .3; profile main images retain colour. Customer has exactly one lock tile showing ongoing count and earliest confirmed future date/time, across shift days; pending-only fallback remains. No customer identity or financial amount is added to the lock screen.

They cover four locales, view composition, source finalization, Tally/zero settlement, full batches/holds, Manager receipt/Boss confirmation, stale reviews, retries, reports, revisions/recovery and shared UI. These checks are not real Telegram/device or external-payment QA. Physical Android/iOS, localization and backend/production acceptance remain separate.
